# 无损压缩与摘要发送选择

本轮基于 `7733f2d2f3e0369ac787fae8af52b7ea126a0023`（插件工具结果图片附件）实现，保留该提交的插件功能。

## 使用方式

- 手动压缩后，原始节点、消息版本、附件与收藏关系保留在数据库中。
- 侧栏当前选中的会话右侧提供“显示／收起压缩前原文”和“压缩摘要”入口。
- 原文显隐只改变显示。展开原文不会把它重新发送给 AI。
- 摘要弹窗支持整体发送开关、逐段勾选、编辑、全选／全不选；可插入换行后点击“按换行拆分”，单独选择其中的内容。
- 点击“保存”后，新设置用于下一次请求；取消或返回会丢弃本次编辑。已经发出的请求不受影响。
- 关闭发送或取消全部勾选时，普通回复和主动消息请求只使用未压缩的近期历史；不会自动恢复发送压缩前原文。
- 再次压缩时，未勾选的旧段保留，并且不参与已选摘要的合并；整体发送关闭时保留全部旧段，不把旧摘要发送给压缩模型。
- “压缩对话历史”的“附加说明”下有“与往期摘要合并”开关，默认开启，保留原来的重新汇总行为。关闭后只压缩本次新覆盖的消息，往期摘要原文、顺序、ID和逐段发送选择保持不变，本次摘要追加在后面；旧摘要不会进入本次压缩请求。
- 关闭往期合并时，本次消息如果分成多块，仍会汇总为本轮摘要。目标 token 作用于本轮摘要，历次保留摘要的总长度可大于该目标；之后可重新开启合并。此开关是每次压缩的选择，不改变摘要发送总开关。
- 摘要管理窗口提供独立“合并已有摘要”按钮，不需要新增消息。按当前编辑草稿和勾选状态，只将已选摘要发送给压缩模型，可选目标 token 与附加说明；未选段完整保留，总发送开关关闭时按钮禁用。
- 独立合并结果先回填编辑框，检查后点击“保存”才生效；取消/失败不写库。保存只更新摘要，不改变原文覆盖范围和压缩恢复点；“撤销最近一次”仍撤销最后一次消息压缩。目标 token 为近似长度，未选段保留的文本不计入合并目标；需要控制全部摘要总量时先全选。
- “撤销最近一次压缩”恢复该轮压缩之前的摘要、逐段选择和发送总开关，只让该轮的原文重新参与上下文选择；更早的历史仍然压缩。确认框会显示恢复条数，可以逐次撤销已保存的恢复点。
- “撤销全部压缩”单独提供并再次确认，显示全部恢复条数及 token 用量提示；同时清空恢复点。只看原文可使用眼睛按钮，不必撤销。
- 睁眼表示当前原文可见，闭眼表示当前原文隐藏；按钮提示仍描述点击动作。
- 恢复点仅在成功提交压缩后保存，取消/失败不增加记录；摘要编辑不会被误算成新一轮压缩。重启、备份恢复和覆盖范围之后的分叉保留恢复点，后来新增的消息不受撤销影响。
- 旧测试包没有保存逐次恢复点，升级时无法还原过去每一轮；新一轮压缩会先保存现有状态，之后可以只撤销这一轮。无恢复点时禁用“撤销最近一次”，不会自动改成撤销全部。
- 压缩前原文保留复制、查看附件与分叉能力；编辑、删除、重新生成和版本切换受限。先撤销压缩或从历史位置分叉后再修改。

没有增加顶栏重复入口或摘要置顶卡片。发送选择按会话持久化，原文显隐按会话的 ViewModel 隔离。

## 数据与请求

数据库 schema32 支持 schema30、旧单段摘要 schema31 和新版分段摘要 schema31 向前升级。此前两轮测试包复用了版本31，但结构不同，导致旧包用户遇到 Room identity 校验失败。
显式30→32／31→32迁移按实际列补齐，旧单段摘要转换为默认选中的新摘要段；已有分段编辑、排除状态与发送总开关原样保留。保留旧 `compressed_summary` 兼容列，避免重建会话父表触发原文节点的级联删除；迁移不删表、不清数据、不跳过Room校验。
当前schema33在32基础上只新增 `compression_history` JSON列，旧记录默认 `[]`。恢复点保存摘要及发送设置、覆盖前缀条数和边界UUID，不复制原文，也不逐轮复制几千个节点ID。
原始 MessageNode 列表是事实来源；显示投影和请求投影均使用同一个有效覆盖前缀。

摘要单独作为历史上下文加入 system 消息，独立于会话自定义提示词开关；普通历史的滑动窗口不会裁掉摘要。
摘要被标记为历史数据，内部引用的指令不作为新指令。请求中的历史只包括未覆盖节点。
普通回复、工具续接、主动消息、拒接辅助回复、标题与建议生成遵循发送选择；归档和跨端完成事件继续使用真实消息。

流式写回按消息 UUID 匹配；重新生成绑定明确的目标节点。压缩前已开始的生成返回旧窗口时，也不得改写后来归档的节点。
压缩提交检查元数据 revision、发送选择和源节点快照，在保存锁内读取最新状态，保留压缩期间追加的消息。
原文编辑、删除、版本切换和摘要提交使用同一个锁；旧 revision 不得覆盖新摘要状态。
历史内部的分叉不继承未来摘要；覆盖之后的分叉重映射覆盖节点 ID。

缺少摘要或全覆盖的损坏记录明确阻止生成，并保留可达的撤销入口。旧备份缺少新字段时默认为未压缩。
旧版本已经用摘要替换掉的原文不能从摘要重建，本轮不猜测或改写那些历史数据。
